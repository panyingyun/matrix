# 阶段 5：AVX2/FMA + 自适应 2D 划分 + 按需打包（当前最优）

## 思路

复用与阶段 3/4 **完全相同**的汇编微内核（[internal/kernel](../internal/kernel/kernel_amd64.s)），
把阶段 4 的三个"固定参数"改成按 `n` 自适应，消除阶段 4 在小尺寸与非对齐尺寸上的塌陷：

| 维度 | 阶段 4（固定） | 阶段 5（自适应） |
| --- | --- | --- |
| 列任务划分 | 16 等分列组，`colsPer = ceil(n/16)` | 固定 64 列一带（16 的整数倍） |
| 行任务划分 | 8 等分，`rowsPer = ceil(n/8)` | 固定 32 行一带 |
| 任务总数 | 恒定 128 | `ceil(n/32) × ceil(n/64)`，随 n 伸缩 |
| 列尾兜底 | 列外层、k 内层（跨行扫打包 B） | k 外层、列内层（连续访问） |
| 打包缓冲区 | 恒按 `kb×jb = 512×64` 分配 | 按每个 k 块的实际 `klen` 分配 |
| 是否打包 | 恒打包 | `n < 720` 免打包，直接算 |

四个关键点：

1. **列带宽度必须是内核宽度（16）的整数倍**。阶段 4 的 `colsPer=ceil(n/16)` 在
   n=192（12 列）、384（24 列）、640（40 列）时不是 16 的倍数，列尾走标量兜底；
   而兜底循环是"列外层、k 内层"，在打包缓冲上以 `jb=64` 个 double（512 B）的步长跳读，
   **每读 1 个 double 就消耗一条 cache line**，把打包换来的局部性又还了回去。
   阶段 5 固定 64 列一带（64 = 4×16），列尾只会出现在最后一个列带，且改为连续访问。
2. **小尺寸不做打包**。n < 720 时单个矩阵 ≤ 4 MiB，能驻留 L3，打包的局部性收益
   抵不过一次完整拷贝 + 分配；实测交叉点落在 704~767 之间（704 免打包快 14%，
   767 打包快 21%，1024 打包快 2.2 倍），故阈值取 720。
3. **按实际长度分配打包缓冲区**。阶段 4 恒分配 `nKK×nJJ×512×64` 个 double，
   n=16 时要分配 256 KiB 去装 2 KiB 的 B；阶段 5 用 `Σ nJJ×klen(kk)×bandCols`。
4. **任务数随 n 伸缩**。阶段 4 恒定派生 128 个任务，n=16 时 128 个 goroutine 去算
   256 个元素；阶段 5 在 n=16 时只有 1 个任务、n=64 时 2 个、n=1024 时 512 个。

## 实测（本机 Core Ultra 7 155H，GOMAXPROCS=22）

`go run ./benchmark -sizes all -repeat 3`，相对同尺寸阶段 1 的加速比：

| n | 阶段 3 | 阶段 4 | 阶段 5 | 阶段 5 单次耗时 | 吞吐 |
| --- | --- | --- | --- | --- | --- |
| 64 | 5.56× | 0.74× | **6.12×** | 0.024 ms | 22 GF/s |
| 96 | 7.88× | 1.02× | **10.8×** | 0.041 ms | 43 GF/s |
| 128 | 7.46× | 1.48× | **17.1×** | 0.063 ms | 67 GF/s |
| 192 | 13.0× | 1.48× | **23.1×** | 0.141 ms | 100 GF/s |
| 256 | 17.9× | 20.2× | **28.6×** | 0.266 ms | 126 GF/s |
| 384 | 17.9× | 3.79× | **31.5×** | 0.730 ms | 155 GF/s |
| 512 | 24.5× | **32.1×** | 27.3× | 2.07 ms | 130 GF/s |
| 640 | 24.8× | 6.02× | **34.0×** | 3.19 ms | 164 GF/s |
| 768 | 28.0× | 35.2× | **35.5×** | 5.54 ms | 164 GF/s |
| 1024 | 24.4× | 36.1× | **38.7×** | 12.01 ms | 179 GF/s |
| 2048 | 21.1× | **75.5×** | 70.5× | 77.9 ms | 221 GF/s |

1024×1024 单次耗时（`go test ./benchmark -bench . -benchtime=2s -count=3` 取均值）：
阶段 5 ≈ 10.4 ms（~206 GF/s），与阶段 4 的 10.4 ms 持平——**阶段 5 的价值在 1024 之外的尺寸**。

结论：

- 阶段 4 只在 `ceil(n/16)` 是 16 的倍数的尺寸（241–256、497–512、753–768、1009–1024…）
  才跑得起来，其它尺寸塌陷 6~10 倍；阶段 5 在 64~1024 全程单调改善，无塌陷点；
- n ≤ 48 时任何划分都拿不到并行收益（矩阵本身在 L1/L2 里），阶段 5 与阶段 3 相当；
- n = 2048 时阶段 4 反而快 7%（±10% 噪声内），两者都是打包路径。
